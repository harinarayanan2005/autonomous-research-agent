1. Executive Summary & Project Purpose

Traditional Large Language Model (LLM) applications suffer from two critical flaws: static cutoff knowledge and hallucination. Most beginner portfolio applications simply wrap an LLM prompt inside an API endpoint, returning pre-trained text without validation.

AutoResearch Agent is a full-stack, production-grade Agentic AI platform. Rather than guessing answers, the system initiates an autonomous ReAct (Reasoning + Acting) loop: it dynamically formulates a hypothesis, issues live web search queries to DuckDuckGo, extracts and scrapes web page content, evaluates the observations, iteratively refines its search trajectory, and compiles an executive intelligence dossier accompanied by quantitative benchmark metric charts.

3. Core Technical Features

A. Autonomous ReAct Orchestration Engine

Implemented in agent_core/agent_engine.py, the agent follows the landmark academic ReAct pattern:

  • Thought: The agent articulates its internal rationale regarding what information is missing.
  • Action: It decides which tool to invoke: search_web or scrape_page.
  • Action Input: It generates the exact search query or URL target.
  • Observation: The tool runs in a sandboxed Python function and returns the live web output.
  • Iteration: The observation is appended into the conversational context for the next decision cycle.

B. Real-Time Streaming via Server-Sent Events (SSE)

Unlike traditional applications that poll the server every few seconds (generating high network overhead and latency), AutoResearch uses a persistent unidirectional HTTP stream via Django's StreamingHttpResponse. As the agent completes individual reasoning steps, events are pushed immediately to the browser using the native W3C EventSource API.

C. Dual-Payload Structured Generation (Metrics + Dossier)

The LLM does not merely return unstructured prose. During synthesis, it outputs a dual payload:

  1. Quantitative Benchmarks: A structured JSON array of scored dimensions (e.g., Performance, Cost-Efficiency, Context Window) scaled 1–100. This data binds dynamically to an interactive Recharts Bar Component.
  2. Executive Dossier: A comprehensive Markdown brief containing Executive Summaries, Technological Pillars, Comparative Matrices, and Sources.

D. Grounded Follow-Up Q&A ("Chat with Dossier")

Users can interrogate the generated research through a follow-up drawer. The backend takes the user's question, injects the compiled report and all raw web observation telemetry into the prompt, and enforces strict grounding to ensure zero hallucinated answers.

E. Side-by-Side Dual Matrix Comparison Mode

A dedicated multi-session view allowing users to select any two past research dossiers and inspect their visual benchmark charts and executive summaries simultaneously.

F. Multi-Page Boxed PDF Export Engine

Utilizes CSS Paged Media standards (@page, position: fixed border cloning, orphans/widows control) to generate a formal, multi-page Microsoft Word-style bordered whitepaper with zero third-party PDF server dependencies.

5. Technical Interview Questions & Model Answers

Q1: How does your application differ from a typical ChatGPT or Gemini wrapper?
"A wrapper simply takes a user prompt, forwards it directly to an LLM API, and displays the response. It cannot access new information and frequently hallucinates. My application implements an autonomous ReAct (Reasoning + Acting) loop: the agent has external agency. It formulates search strategies, calls DuckDuckGo and web-scraping tools, reads intermediate results, iteratively refines its search trajectory, and saves an immutable audit trail of its decisions into a relational database."
Q2: Why did you choose Server-Sent Events (SSE) over WebSockets?
"WebSockets provide full-duplex, bidirectional communication over a dedicated TCP connection, which is ideal for multiplayer games or collaborative whiteboards. However, an AI research agent only streams data in one direction—from server to client. Server-Sent Events (SSE) operate over standard HTTP, require zero protocol-upgrade handshakes, traverse corporate firewalls cleanly, and include automatic connection re-establishment natively built into the browser's EventSource API. It is lighter and architecturally tailored for LLM token and step streaming."
Q3: How did you handle API rate limits (HTTP 429) and high-demand spikes (HTTP 503)?
"I engineered an automated exponential backoff retry decorator in agent_core/agent_engine.py. When Google AI Studio returns a 429 Resource Exhausted or 503 Temporary Spike error, the engine intercepts the exception, dynamically calculates a backoff sleep interval, and retries the request up to four times before falling back to graceful local synthesis. Additionally, the agent loop executes in an asynchronous Python background thread, ensuring that slow tool calls or rate limits never freeze the Django HTTP request/response cycle."
Q4: How do you prevent hallucination during the follow-up Q&A chat?
"I implemented strict Retrieval Grounding. When a user asks a follow-up question, the backend queries the database for all recorded AgentStep observations and the synthesized report. These verified web snippets are injected directly into the LLM system prompt as context, with an explicit constraint instructing the model to answer exclusively from the provided observations and state if an answer cannot be verified from the data."
